## 本阶段需要确认的流程

1. 创建目标流程。
2. AI 生成计划流程。
3. 修改和确认计划流程。
4. 每日打卡流程。
5. 提醒、延后和重新安排流程。

每项流程逐步确认，不在本阶段决定页面布局、按钮位置或视觉样式。

## 已确认的跨流程规则

- 创建目标只从“目标”一级入口发起。
- 用户可以选择 AI 创建或手工创建。
- 用户最初只需要输入目标描述，AI 最多追问三轮。
- 未配置 API 时允许配置、切换为手工创建或退出并保留草稿。
- 关键输入和中间结果及时保存在本地。
- AI 计划只能成为草稿，用户确认后才能生效。
- 已确认计划需要修改时，新内容先成为草稿，不直接覆盖正式计划。
- 今日入口包含逾期任务和今日任务。
- 每个任务最多安排一次有效系统通知。
- 用户可以完成、延后、跳过、删除或重新安排任务。

## 1. 创建目标流程

### 1.1 已确认流程

```text
目标
→ 发起创建目标
→ 输入目标描述
→ 选择 AI 规划或手工规划
├─ AI 规划
│  → AI 分析并建议目标类型
│  → 用户确认或修改目标类型
│  → AI 追问与目标条件确认
│  → AI 计划草稿
└─ 手工规划
   → 用户选择目标类型
   → 用户填写目标条件
   → 手工计划草稿
→ 进入计划审核
```

确认规则：

- 用户先表达目标，再决定采用 AI 或手工规划。
- 同一份目标描述可以直接用于任一规划路径。
- AI 路径中，AI 只提供期限型目标或长期习惯的类型建议，用户拥有最终决定权。
- 手工路径不调用 AI，目标类型由用户自行选择。
- 用户修改 AI 建议的目标类型后，后续追问和计划规则以用户选择为准。
- 选择手工规划后，仍可在草稿阶段主动改用 AI；切换前保留已有输入。
- 选择 AI 后遇到 API 问题，可以改用手工规划；已有目标描述和回答不得丢失。

流程中断时：

- 自动保存已经输入的目标描述和回答。
- 再次进入时允许继续草稿。
- API 或网络失败不能清除草稿。
- 用户主动删除草稿时才移入最近删除或清除，具体操作表现留到页面原型阶段。

## 2. AI 生成计划流程

### 2.1 已确认流程骨架

```text
选择 AI 规划
→ 检查 API 配置
├─ 无可用配置
│  → 配置 API / 改用手工规划 / 保存退出
└─ 有可用配置
   → 显示本次使用的 API 配置并允许切换
   → 用户确认调用
   → AI 建议目标类型
   → 用户确认或修改类型
   → AI 追问缺失信息（最多三轮）
   → 用户检查目标条件和 AI 假设
   → 用户确认目标条件
   → 显示计划生成所用 API 配置并允许切换
   → 用户确认生成
   → AI 返回计划
   ├─ 返回有效：保存为计划草稿并进入审核
   └─ 返回异常：保留全部输入，进入错误处理
```

固定规则：

- 每次实际调用前显示当前 API 配置并允许切换。
- 不自动调用备用配置。
- 最多进行三轮追问。
- 用户可以提前结束追问。
- 第三轮后仍缺信息时，显示缺失项和 AI 假设，由用户决定补充或继续。
- 目标条件必须经用户确认后才能生成计划。
- 生成过程中允许取消；取消后保留目标和回答。
- 有效结果先保存为本地草稿，不直接生成正式任务。

### 2.2 待确认核心决策

已确认：

- 每轮提出一组相互相关的问题，最多三轮。
- AI 返回格式错误或缺少必要内容时，不自动发起新的 API 调用。
- 异常时保留目标、回答和已有结果，由用户选择重新生成、切换配置、手工修改或退出保存。
- 用户选择重新生成时，仍需重新显示当前 API 配置并确认调用。

## 3. 修改和确认计划流程

### 3.1 已确认流程骨架

```text
计划草稿生成或手工建立
→ 用户查看阶段、任务、时间、预计用时、完成标准和依赖
→ 用户进行修改
→ 软件执行基础校验
├─ 存在明显时间冲突：提示，但允许继续
├─ 存在必要信息缺失：按待确认规则处理
└─ 校验通过或用户处理提示
→ 用户确认计划
→ 草稿转为正式计划和任务
→ 安排有效系统通知
→ 进入目标概况
```

已确认规则：

- 用户可以新增、修改、删除和调整草稿任务。
- 用户可以调整阶段、顺序、时间和提示型依赖。
- 时间冲突只提示，不强制阻止确认。
- 重新生成时保留最近一个旧草稿。
- 草稿未经确认不生成正式任务和通知。
- 执行中的目标重新规划时，只替换未处理任务，保留已完成和已跳过记录。
- 删除或被替换的未处理任务不再计入当前计划完成率。

### 3.2 待确认核心决策

已确认：

- AI 支持整份重新生成，也支持选中阶段或任务进行局部调整。
- 局部 AI 调整仍先生成草稿，用户确认后才写入计划。
- 局部调整可能影响时间或依赖时，重新执行冲突和依赖检查。
- 核心字段错误会阻止确认；普通问题只提示，用户可以继续。
- 核心错误至少包括：任务没有名称、没有日期或可执行顺序、开始时间晚于截止时间。
- 普通警告至少包括：任务时间冲突、预计用时缺失、前置任务尚未完成。
- 不自动调用 AI 补齐缺失字段。
- 执行中重新规划被替换的旧任务保存在目标记录中，并标记为“已被计划替换”。
- 被替换任务不再参与当前计划、通知和完成率，但历史内容可以查看。

## 4. 每日打卡流程

### 4.1 已确认流程骨架

```text
今日
→ 查看逾期任务和今日任务
→ 选择任务
├─ 标记完成
├─ 延后
├─ 跳过
└─ 查看或编辑详情
```

任务完成时：

- 立即保存已完成状态和实际完成时间。
- 取消尚未触发的任务通知。
- 更新所属阶段、习惯和目标进度。
- 逾期后完成仍记为已完成，同时保留实际完成时间供记录使用。
- 前置任务未完成时进行提示，但允许用户继续完成当前任务。
- 用户可以取消完成，恢复为待完成状态。

### 4.2 待确认核心决策

已确认：

- 普通任务可以直接标记完成，不要求进入详情或二次确认。
- 完成后提供短时间撤销机会；具体时长和视觉形式留到页面原型阶段。
- 用户可以随时取消完成。
- 如果目标已经确认完成，取消其中任务前提示目标将重新进入执行状态。
- 用户确认取消后，任务恢复为待完成，目标恢复执行状态，并重新计算进度。
- 如果恢复任务的提醒时间已经过去，不自动发送补发通知；任务按逾期规则显示。
- 最后一个任务完成或习惯阶段达成后，立即给出非强制提示。
- 用户可以现在处理，也可以稍后处理。
- 稍后处理时，期限型目标保持“待完成确认”，长期习惯阶段保持“已达成待继续”。
- 用户处理时再播放相应鼓励动画并进入后续选择。

## 5. 提醒、延后和重新安排流程

### 5.1 已确认流程骨架

```text
任务到达有效提醒节点且仍为待完成
→ iOS 发送一次系统通知
→ 任务继续保留在今日或逾期任务中
→ 用户打开或处理任务
├─ 完成
├─ 延后
├─ 跳过
└─ 查看详情并重新安排
```

固定规则：

- 每个有效提醒安排最多发送一次通知。
- 完成、跳过、删除任务或暂停目标后，取消尚未触发的通知。
- 修改任务时间后取消旧通知，并按新提醒节点安排一次新通知。
- 延后已经提醒过的任务后，新时间可以获得一次新通知。
- 通知未被用户处理时，软件不持续重复催促。
- 任务逾期后继续保留在“今日”的逾期任务范围。
- 延后产生时间冲突时进行提示，但允许用户继续。
- 软件不未经确认自动修改其他目标的任务。

### 5.2 待确认核心决策

已确认：

- 系统通知提供“完成”和“延后”快捷操作；点击通知正文进入对应任务详情。
- “跳过”、编辑和其他操作进入应用内处理。
- 从通知直接完成任务时，立即保存完成状态、实际完成时间并更新进度。
- 从通知执行延后时，提供常用快捷时间，也允许进入应用自定义日期和时间。
- 快捷延后或自定义延后成功后，取消旧通知并按新时间安排一次通知。
- 延后首先只修改当前任务，不自动改变后续任务。
- 当前任务延后完成后，提示用户是否需要调整同一计划的后续任务。
- 用户可以不调整、手工调整，或让 AI 生成后续调整草稿。
- AI 调整需要重新显示 API 配置并由用户确认调用。
- 后续调整草稿经过审核确认后才生效。
- 其他目标的任务不会被自动改变。
- 通知快捷操作的具体系统可行性将在阶段六验证；若系统版本存在限制，应保持“点击通知正文进入任务详情”的完整备用路径。

## 已确认用户流程总览

```text
创建目标
→ 输入目标描述
→ 选择 AI 或手工规划
→ 确认目标类型和目标条件
→ 形成计划草稿
→ 审核、修改和校验
→ 用户确认计划
→ 生成正式任务和通知
→ 在今日、日历或目标中执行任务
→ 完成 / 延后 / 跳过 / 删除 / 重新安排
→ 更新阶段和目标进度
→ 阶段达成或目标待完成确认
→ 用户现在处理或稍后处理
→ 鼓励反馈及后续选择
```

## 延后到页面原型阶段的非阻塞事项

- 创建目标各步骤在页面中的具体承载方式。
- AI 追问采用聊天、表单或混合形式。
- 草稿修改、局部 AI 调整和错误提示的具体交互控件。
- 今日任务的一键完成按钮位置及撤销提示形式。
- 阶段达成和目标完成提示的具体展示方式。
- 通知快捷操作进入应用后的具体视觉反馈。
- 延后快捷选项的具体数量、名称和按钮排列。
