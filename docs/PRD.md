## 已确认事项摘要

- 第一版为中文 iOS 手机应用，Android 后续支持。
- 主要供个人使用，不需要注册登录。
- 数据优先保存在本地，并建立本机恢复副本。
- 使用手机系统通知，每个任务最多发送一次有效通知。
- 支持用户自行配置多套大模型 API，并在每次调用前确认当前配置。
- 同时支持期限型目标和长期习惯，允许多个目标并行执行。
- 支持 AI 追问、AI 生成计划、手工计划、用户审核、修改和确认。
- 未经用户确认，AI 不得直接修改正式计划。
- 支持任务打卡、延后、跳过、删除、恢复和重新安排。
- 支持目标暂停、恢复、完成、终止、删除和恢复。
- 目标或习惯达成时提供鼓励动画。
- 暂不开发云同步、付费、社交和团队协作功能。

## 1. 产品名称

正式名称：**橙橙计划**。

产品名称已由用户确认。图标、宣传语和品牌视觉尚未确认，将在阶段五“视觉设计”中讨论。

## 2. 产品背景

许多用户知道自己想完成什么，却很难将一个目标拆解成清晰、合理且可以执行的日常任务。

普通待办应用要求用户自行制定全部计划；通用大模型能够给出建议，但模型生成结果通常与任务管理、日期安排、打卡和系统通知相互分离。用户需要手工复制和整理，执行成本较高。

橙橙计划希望连接以下过程：

1. 用户描述目标和要求。
2. AI 通过追问补充必要信息。
3. AI 将目标拆解成计划草稿。
4. 用户审核并修改计划。
5. 用户确认后，软件将计划转为按日期和时间排列的任务。
6. 用户通过打卡和系统通知推进计划。
7. 用户根据实际情况持续调整目标和任务。

## 3. 产品定位

橙橙计划是一款面向个人用户的中文 AI 计划生成与任务提醒手机应用。

产品重点是：

- 帮助用户把模糊目标变成可执行计划。
- 通过 AI 降低规划成本，但不让 AI 代替用户作最终决定。
- 让用户在计划生效前完整审核和修改。
- 通过日期、时间、打卡和系统通知推动执行。
- 允许用户在现实情况变化时暂停、延后或重新规划。
- 让个人数据优先保存在本地，并由用户选择大模型服务。

第一版不定位为团队项目管理工具、社交打卡平台、专业日历替代品或通用 AI 聊天助手。

## 4. 目标用户

### 4.1 主要用户

- 希望制定学习、备考或课程计划的学生和自学者。
- 希望推进个人项目、作品或技能目标的用户。
- 希望培养阅读、运动、早睡等长期习惯的用户。
- 已经使用大模型，但不愿手工把模型回答整理成日程的用户。
- 希望自行选择模型服务并控制个人计划数据的用户。

### 4.2 用户特征

- 使用中文。
- 能够进行基本手机操作。
- 愿意描述目标并回答补充问题。
- 可能了解 API Key，也可能需要清楚的配置说明。
- 对个人计划数据和 API Key 的安全性有要求。

### 4.3 第一版不重点服务

- 需要多人协作和任务分派的团队。
- 需要跨设备实时同步的用户。
- 需要企业权限、审计和管理后台的组织。
- 需要复杂资源管理、甘特图和强制依赖的专业项目经理。
- 需要医疗、法律、投资等专业决策建议的用户。

## 5. 用户需要解决的问题

1. 目标模糊，不知道从哪里开始。
2. 不知道如何将长期目标拆成阶段任务和每日任务。
3. 手工安排任务耗时且容易遗漏。
4. AI 计划可能不符合个人时间和实际能力，需要方便地审核修改。
5. 计划生成后缺少持续提醒，容易中断。
6. 临时情况发生时，原计划难以快速延后或重新安排。
7. 普通待办工具和 AI 工具相互分离。
8. 用户希望自行选择模型服务并控制个人数据。
9. 用户需要清楚地知道 AI 计划只是建议，不能保证目标一定完成。

## 6. 产品核心价值

核心价值主张：**把用户的目标转化为经过用户确认、能够按时执行并可以持续调整的任务计划。**

- 降低规划成本：AI 提供计划初稿。
- 保留用户控制权：AI 结果必须由用户审核确认。
- 推动实际执行：任务具有日期、时间、状态和提醒。
- 适应现实变化：计划可以暂停、延后或重新生成。
- 提供正向反馈：阶段和目标达成后播放鼓励动画。
- 尊重隐私：主要数据本地保存，明确说明发送给模型的数据。
- 减少服务绑定：允许保存和切换多套兼容的大模型配置。

## 7. 核心使用场景

### 7.1 期限型目标

用户输入“30天完成某课程”等目标。AI 追问截止日期、可投入时间和限制条件，生成按日期安排的任务。用户修改并确认后开始执行。

### 7.2 长期习惯

用户输入“长期坚持阅读”等目标。AI 追问执行频率、时间和阶段要求，再生成重复任务。习惯可以不设置结束日期。

### 7.3 多目标并行

用户可以同时执行学习目标、个人项目和长期习惯。不同目标任务发生时间冲突时，软件提示用户，但允许用户继续确认。

### 7.4 计划临时中断

用户可以暂停整个目标。暂停期间停止未来通知，恢复时由用户处理过期任务或要求 AI 重新规划。

### 7.5 任务到期未完成

任务到达用户选择的提醒节点且仍未完成时，系统发送一次通知。用户随后可以完成、延后、跳过或重新安排。

### 7.6 阶段和目标达成

长期习惯达成阶段条件后播放阶段鼓励动画；期限型目标的任务处理完后，由用户确认目标是否真正达成，再播放目标完成动画。

## 8. 完整用户使用流程

1. 用户首次打开应用。
2. 软件说明本地存储、通知权限、AI 使用方式和必要风险。
3. 用户配置大模型 API，或暂时跳过。
4. 用户创建目标并输入目标描述。
5. 用户选择使用 AI 或完全手工创建计划。
6. 使用 AI 时，软件在调用前显示当前 API 配置并允许切换。
7. AI 分析目标并在最多三轮内追问缺失信息。
8. 用户检查 AI 整理出的目标条件和关键假设。
9. 用户确认目标条件。
10. AI 生成计划草稿；或用户手工建立计划草稿。
11. 用户审核、修改、新增、删除和调整草稿任务。
12. 软件检查时间冲突、缺失字段和不合法日期。
13. 用户确认计划。
14. 软件生成正式任务并安排有效通知。
15. 用户查看和执行任务。
16. 用户完成任务后打卡。
17. 到达提醒节点仍未完成时，系统发送一次通知。
18. 用户可以延后、跳过、删除或重新安排任务。
19. 用户可以修改、暂停、恢复或重新规划目标。
20. 重新规划只替换未处理任务，已完成和已跳过记录保留。
21. 期限型目标的任务全部处理后，用户确认目标是否达成。
22. 长期习惯达成阶段条件后，用户决定是否继续下一阶段。
23. 用户确认完成目标后播放相应鼓励动画。

该流程只描述业务顺序，不代表页面结构或页面布局。

## 12. 各功能模块具体需求

### 12.1 首次使用与权限

- 说明产品用途和本地优先原则。
- 明确 AI 内容可能有误，必须由用户审核。
- 明确目标内容会发送给用户选择的模型服务商。
- 在需要通知时申请系统通知权限。
- 用户拒绝权限后仍可使用其他功能，并明确提示提醒不可用。

### 12.2 大模型 API 配置

每套配置至少包含：

- 用户自定义名称。
- API 地址。
- API Key。
- 模型名称。
- 最近连接测试结果。

规则：

- 支持保存多套配置。
- 用户设置一套默认配置。
- 每次调用前显示当前配置并允许临时切换。
- 不自动调用备用配置。
- API Key 默认隐藏，不写入普通日志和业务恢复副本。
- 删除配置不能删除由该模型生成的历史业务数据。
- 具体兼容协议和安全存储方式待阶段六确认。

### 12.3 目标管理

每个目标至少包含：

- 目标名称或描述。
- 目标类型。
- 创建时间。
- 当前状态。
- 已确认的目标条件。
- 关联计划、阶段和任务。

目标状态包括：

- 草稿。
- 追问中。
- 待生成。
- 待审核。
- 执行中。
- 已暂停。
- 待完成确认。
- 已完成。
- 已终止。

允许多个目标同时处于执行中。

### 12.4 AI 追问

- 用户最初只需输入目标描述。
- AI 根据目标判断还缺少哪些信息。
- 最多追问三轮。
- 用户可以修改回答或提前结束追问。
- 达到三轮仍有缺失信息时，列出缺失项和 AI 假设。
- 关键假设必须由用户确认。
- API 或网络失败不能清除目标和已有回答。

### 12.5 AI 计划生成

- 由用户主动发起，不允许后台擅自调用。
- 调用前检查配置和网络状态。
- AI 结果先保存为本地草稿。
- 解析失败时不转为正式任务。
- 用户确认前不得安排正式通知。

每项 AI 任务应尽量包含：

- 任务名称。
- 完成说明。
- 日期或顺序。
- 开始时间和截止时间，如适用。
- 预计用时。
- 完成标准。
- 所属阶段和前置任务，如适用。
- 建议提醒节点。

### 12.6 手工计划

- 不需要 API 和网络。
- 用户可以手工填写目标条件、阶段和任务。
- 手工计划同样经过草稿、校验和确认后生效。
- AI 失败后允许转为手工创建，已有内容不能丢失。

### 12.7 计划审核

用户可以：

- 查看计划概况和任务详情。
- 修改任务名称、说明、日期、时间、预计用时和完成标准。
- 新增、删除或调整草稿任务。
- 调整阶段和任务顺序。
- 修改依赖关系。
- 重新生成计划。
- 恢复最近一个旧草稿。
- 确认计划。

确认前检查：

- 必要字段是否完整。
- 日期和时间是否合法。
- 开始时间是否晚于截止时间。
- 是否存在明显时间冲突。
- 任务是否超出目标期限。
- 提醒节点是否有效。

冲突只提示，不阻止用户确认。

### 12.8 任务管理

任务字段可以包括：

- 所属目标和阶段。
- 任务名称和说明。
- 完成标准。
- 日期、开始时间和截止时间。
- 预计用时。
- 提醒开关和提醒节点。
- 当前状态和实际完成时间。
- 前置任务。
- 调整记录。

正式任务状态只有：

- 待完成。
- 已完成。
- 已跳过。

逾期由时间动态判断，不作为独立保存状态。

### 12.9 任务依赖

- 支持一个或多个前置任务。
- 前置任务未完成时只提示，不禁止执行后续任务。
- 前置任务被跳过或删除时提示依赖可能失效。
- 删除被依赖任务前说明影响。
- MVP 不自动移动依赖任务的时间。

### 12.10 任务执行

- 用户可以标记完成并保存实际完成时间。
- 用户可以取消完成。
- 完成后取消尚未触发的通知。
- MVP 不支持部分完成和单独的进行中状态。

### 12.11 长期习惯

支持两种阶段方式：

1. 连续完成一定天数。
2. 在指定周期内完成一定次数。

连续模式：

- 只统计计划执行日。
- 跳过或错过任务会中断当前连续纪录。
- 下次完成时重新计算连续纪录。
- 保留历史最佳连续纪录。
- MVP 不提供补签。

周期次数模式：

- 每个周期独立统计。
- 达成目标次数后播放一次阶段鼓励动画。
- 未达成时记录结果并自动开始新的统计周期。
- 未完成次数不顺延。
- 超额完成可以记录，但同一周期不重复播放动画。

阶段达成后不自动创建下一阶段。用户可以按原规则继续、调整后继续、暂不继续或最终完成目标。

### 12.12 鼓励反馈

- 期限型目标确认完成后播放目标完成动画。
- 长期习惯阶段达成后播放阶段鼓励动画。
- 长期习惯最终完成后播放目标完成动画。
- 同一完成事件不应反复自动播放。
- 动画样式、时长、声音和是否允许跳过待阶段五确认。

### 12.13 本地数据管理

需要及时保存：

- 目标和状态。
- AI 追问及用户回答。
- 目标条件和关键假设。
- 计划草稿及最近一个旧草稿。
- 正式计划、阶段和任务。
- 打卡、跳过、延后和调整记录。
- 提醒设置和基础偏好。

本机恢复副本不包含 API Key。

以下情况不得造成已经成功保存的数据重置：

- 手机关机或重启。
- 应用退出或被系统结束。
- 普通应用崩溃。
- 网络或 API 请求失败。
- 兼容版本的应用升级。

### 12.14 最近删除

- 删除任务后进入最近删除并取消通知。
- 删除目标时，其计划、阶段、任务和历史整体进入最近删除。
- 保留期内允许恢复。
- 恢复后重新检查时间、依赖和通知。
- 保留期限待后续确认。

## 13. 目标创建流程

1. 用户输入目标描述。
2. 用户选择 AI 创建或手工创建。
3. AI 创建时显示当前 API 配置并允许切换。
4. AI 分析目标并追问缺失信息，最多三轮。
5. 用户检查并修改整理后的目标条件。
6. 用户确认目标条件。
7. AI 生成计划草稿，或用户手工建立草稿。
8. 用户进入计划审核。

AI 不可用时必须保留目标和回答，并允许切换配置、稍后重试或转为手工创建。

新建目标采用单页还是分步骤填写，待阶段四确认。

## 14. AI 生成计划流程

### 14.1 目标追问阶段

1. 保存用户输入。
2. 检查网络和 API 配置。
3. 显示当前配置并由用户确认调用。
4. AI 判断目标类型和缺失信息。
5. 用户回答问题。
6. 最多进行三轮。
7. 用户确认整理后的目标条件和假设。

### 14.2 计划生成阶段

1. 用户发起生成。
2. AI 返回结构化计划。
3. 软件解析并检查必要字段。
4. 成功后保存为本地草稿。
5. 失败时保留原输入和已有草稿。
6. 用户进入计划审核。
7. 用户确认后才生成正式任务。

## 15. 计划审核和修改流程

1. 展示计划草稿。
2. 用户检查阶段、任务、时间、预计用时、完成标准和依赖。
3. 用户进行手工修改。
4. 软件提示时间冲突和缺失信息。
5. 用户可以忽略冲突继续确认。
6. 用户可以重新生成；替换时保留最近一个旧草稿。
7. 用户确认计划。
8. 软件生成正式任务并安排通知。

执行中的目标重新规划时：

- 保留已完成和已跳过记录。
- 只重新生成未处理任务。
- 新计划未经确认不替换当前正式计划。
- 确认后更新受影响通知。

## 16. 任务打卡流程

1. 用户选择待完成任务。
2. 用户执行完成操作。
3. 软件立即保存已完成状态和实际完成时间。
4. 取消尚未触发的通知。
5. 更新阶段和目标进度。
6. 用户可以取消完成。
7. 如果恢复后的任务已经逾期，按逾期规则显示。

完成按钮的位置和样式待阶段四确认。

## 17. 到期提醒逻辑

- 使用 iOS 系统通知。
- 每个任务最多安排一次有效通知。
- 只有开启提醒且具有有效提醒节点的待完成任务才安排通知。
- 用户可选择开始时间、截止时间或单独提醒时间作为节点。
- 只有日期的任务如需提醒，必须单独设置提醒时间。
- 任务完成、跳过、删除或目标暂停后取消未来通知。
- 修改时间后取消旧通知并安排新通知。
- 延后已提醒任务后，新日期可以重新安排一次通知。
- 权限被拒绝时仍可使用其他功能，并显示提醒受限状态。
- 系统专注模式、权限和省电机制可能导致用户未及时看到通知，产品不承诺绝对准时。

通知文案、提前提醒和快捷操作待后续阶段确认。

## 18. 延后、跳过、删除和重新安排规则

### 18.1 延后

- 用户设置新日期或时间。
- 更新任务和通知。
- 保留调整记录。
- 不自动移动其他目标的任务。

### 18.2 跳过

- 任务状态变为已跳过。
- 取消通知。
- 不计为完成，但从待处理任务中移除。
- 连续习惯中跳过会中断当前连续纪录。

### 18.3 删除

- 删除前提示影响。
- 取消通知。
- 进入最近删除。
- 删除未处理任务后，从当前计划完成率分母移除。

### 18.4 重新安排

- 用户可以手工修改日期、时间、顺序和依赖。
- AI 重新规划先生成草稿，用户确认后生效。
- 不修改已完成和已跳过记录。
- 更新所有受影响通知。

### 18.5 暂停目标

- 保留目标和任务。
- 停止该目标未来通知。
- 暂停期间不自动判定习惯失败。
- 恢复时由用户处理过期任务或重新规划。
- 不自动整体后移任务。

## 19. 异常情况与错误处理

### 19.1 API 异常

包括 API Key 错误、地址错误、模型不存在、余额不足、限额或格式不兼容。

- 使用中文说明可能原因。
- 不显示完整 API Key。
- 不删除目标、回答和已有草稿。
- 允许重试、切换配置或转为手工计划。

### 19.2 网络异常

- 无网络时不发起请求。
- 请求中断时保留全部已有输入。
- 防止重复请求产生重复计划。
- MVP 默认手工重试，不自动轮流调用其他配置。

### 19.3 AI 返回异常

- 空内容、无法解析、缺少必要字段或日期不合法时，不转为正式任务。
- 允许重新生成或手工修改。
- 对医疗、法律、投资等高风险内容提示用户寻求专业复核。

### 19.4 通知异常

- 权限关闭或系统限制时显示提醒受限。
- 通知失败不应删除任务。
- 恢复权限后重新检查未来任务。

### 19.5 数据异常

- 避免半条数据覆盖完整数据。
- 防止重复确认产生重复任务。
- 主数据读取失败时尝试有效恢复副本。
- 数据异常时不得静默清空或覆盖原内容。
- 恢复后提示用户发生过数据恢复。

### 19.6 时间异常

- 提示过去时间、开始晚于截止、超出目标期限和明显冲突。
- 用户跨时区或修改系统时间后重新检查未来通知。
- 不未经确认自动移动任务。

## 20. 数据安全和隐私要求

### 20.1 本地数据

- 主要业务数据保存在设备本地。
- 不收集与核心功能无关的数据。
- 不在用户不知情时上传完整本地数据。
- 删除应用、设备损坏或恢复出厂设置仍可能造成数据丢失，需要明确说明。

### 20.2 API Key

- 默认隐藏。
- 不进入普通日志和业务恢复副本。
- 不发送给用户配置服务之外的第三方。
- 具体安全存储方式待阶段六确认。

### 20.3 发送给模型的数据

可能发送：

- 当前目标描述。
- 当前目标的计划要求和限制条件。
- 当前目标相关任务。
- 用户要求 AI 修改的内容。

原则上不发送：

- 无关目标和完整本地数据库。
- 联系人、位置、照片等未授权信息。
- 设备中与计划无关的敏感数据。

### 20.4 第三方风险

- 模型服务商可能按照自身规则保存或处理请求。
- 调用可能产生第三方费用。
- 用户不应输入密码、身份证号和银行卡号等敏感信息。
- AI 内容不是专业意见。

## 21. 非功能需求

### 21.1 易用性

- 中文表达清楚。
- AI 草稿、已确认计划和正式任务必须能够区分。
- 错误信息说明原因和下一步操作。
- 不要求普通用户理解复杂模型参数。

### 21.2 性能

- 本地目标和任务应快速打开。
- 普通本地操作不依赖网络。
- AI 生成期间显示明确状态。
- 具体性能指标待技术阶段评估。

### 21.3 稳定性

- 应用退出、被系统回收或手机重启后数据保持正确。
- 重复点击不产生重复计划和任务。
- 任务与通知保持一致。
- API 失败不影响已有本地计划。

### 21.4 兼容性

- MVP 平台为 iOS。
- Android 后续支持。
- 最低系统版本待阶段六确认。

### 21.5 可访问性

- 考虑系统字体缩放。
- 保持足够文字对比度。
- 状态不能只用颜色区分。
- 关键操作具有明确文字说明。

### 21.6 数据持久性

- 关键操作后立即保存。
- 长内容编辑过程中定期保存草稿。
- AI 请求发出前保存用户输入。
- AI 返回后先保存草稿再进入审核。
- 通知更新失败不能回滚或删除任务。

### 21.7 成本透明

- 调用 AI 前显示当前模型配置。
- 告知用户可能产生第三方费用。
- 不自动切换或调用其他配置。

## 22. MVP 验收标准

### 22.1 目标和计划

- 无需注册即可创建多个目标。
- 支持期限型目标和长期习惯。
- 支持 AI 追问、AI 生成和完全手工创建。
- AI 结果未经确认不会成为正式任务。
- 用户能够修改、恢复和确认草稿。
- 暂停和恢复目标不会丢失数据。

### 22.2 任务执行

- 确认后的计划能够生成正式任务。
- 任务支持日期、开始时间、截止时间和独立提醒时间。
- 用户能够完成、取消完成、延后、跳过、删除和恢复任务。
- 应用重启后任务状态保持正确。

### 22.3 提醒

- 获得权限后能够安排一次有效系统通知。
- 修改时间后通知同步更新。
- 完成、跳过、删除或暂停后不再发送无效通知。
- 权限被拒绝时能够明确提示。

### 22.4 长期习惯

- 连续天数和周期次数两种模式均能正确统计。
- 连续纪录中断后保留历史最佳纪录。
- 一个阶段只自动触发一次鼓励动画。
- 阶段达成不会错误完成整个目标。

### 22.5 调整和依赖

- 时间冲突产生提示但不阻止确认。
- 前置任务未完成时提示但不禁止执行。
- 重新规划不会修改已完成和已跳过记录。
- 新计划未经确认不会替换正式计划。

### 22.6 数据与隐私

- 关机、重启、系统回收和普通崩溃不会重置已成功保存的数据。
- 主数据异常时能够尝试读取本机恢复副本。
- API Key 不出现在业务恢复副本和普通日志中。
- API、网络或解析失败不会破坏已有数据。
- 删除目标和任务后能够从最近删除恢复。

### 22.7 鼓励反馈

- 期限型目标由用户确认完成后播放一次完成动画。
- 长期习惯阶段达成后播放一次阶段动画。
- 长期习惯最终完成后播放一次目标完成动画。
