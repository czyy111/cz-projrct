## 1. 开发目标

按照已经确认的产品与技术文档，逐步实现可在用户 iPhone 16 Pro Max（iOS 26.6）上通过 Expo Go 验证的“橙橙计划”MVP。

开发过程优先保证：

- 已保存的数据不会因应用退出、系统回收或手机重启而重置。
- 目标、AI 草稿、正式计划、任务、打卡和通知之间保持一致。
- API Key 与普通业务数据分离。
- DeepSeek、豆包及其他兼容模型通过统一配置接入。
- 每个开发步骤都产生可以检查的结果，不一次性开发全部功能。
- 未完成真实验证的原生能力必须明确标注，不用模拟结果代替验收。

## 2. 开发阶段边界

在用户明确回复“开始开发”以前，禁止：

- 创建 React Native 或 Expo 项目。
- 安装 npm、Expo 或其他依赖。
- 创建数据库文件或数据库结构。
- 编写程序代码、测试代码和构建脚本。
- 登录或配置 Expo、Apple、DeepSeek、火山方舟等账号。
- 发起收费模型调用或生成 iOS 构建。

“开始开发”只授权按照本计划从步骤一开始实施，不代表自动授权：

- 购买 Apple Developer Program。
- 上架 App Store。
- 使用用户真实 API Key 进行收费测试。
- 删除或覆盖用户已有文件。
- 擅自增加 PRD 以外的新功能。

## 3. 总体实施原则

### 3.1 小步交付

- 每次只推进一个开发步骤或一组不可分割的紧密任务。
- 每一步完成后说明修改的文件、实现结果、测试结果和仍未验证的内容。
- 发现方案与已确认文档冲突时立即暂停，先更新对应设计文档，不在代码中自行改变产品决定。

### 3.2 验收优先

- 先定义该步骤的检查方法，再实施功能。
- 数据、通知和 AI 解析等高风险逻辑必须有自动测试。
- 页面外观以已确认的页面原型和视觉设计为准，不在开发阶段重新决定布局。

### 3.3 数据安全

- 不把真实 API Key 写入项目、命令、截图、日志或测试文件。
- 数据库升级只允许迁移，不允许以“方便开发”为由清空用户数据。
- 删除和恢复流程使用测试数据验证，不对用户真实数据进行破坏性实验。

## 4. 开发步骤

## 步骤一：项目基础与开发环境

### 修改内容

- 在用户确认开始开发后创建 Expo＋React Native＋TypeScript 项目。
- 建立基础目录、配置文件、代码规范、测试入口和环境变量示例。
- 配置 Expo Router、基础错误边界和开发环境检查。
- 只加入当前步骤明确需要的依赖，不一次安装所有候选库。

### 产生结果

- Windows 上可以启动开发服务。
- iPhone 可以通过 Expo Go 打开空白应用骨架。
- 项目名称显示为“橙橙计划”的开发预览标识。
- 项目中不存在真实密钥。

### 验收

- TypeScript 检查通过。
- 最小自动测试通过。
- Expo Go 能加载并在断开后重新连接开发服务。

## 步骤二：设计基础与导航骨架

### 修改内容

- 根据《视觉设计》建立颜色、字体、间距、圆角、阴影、动效开关等设计变量。
- 根据《信息架构》和《页面原型》建立已确认的页面路由与导航外壳。
- 建立通用加载、空状态、错误提示、确认对话框和表单控件。
- 暂不填充完整业务页面。

### 产生结果

- 用户可以在主要导航入口之间切换。
- 浅色、深色和减少动态效果规则具备统一基础。
- 后续页面复用同一套视觉规则。

### 验收

- 页面名称和跳转关系与已确认信息架构一致。
- 不新增未经确认的导航入口。
- iPhone 安全区域、文字缩放和基础键盘交互正常。

## 步骤三：数据模型、SQLite 与恢复机制

### 修改内容

- 建立目标、阶段、计划草稿、任务、任务依赖、操作记录、提醒配置和基础偏好的数据结构。
- 建立 SQLite 初始化、事务、版本迁移和数据访问层。
- 建立关键操作立即保存、长文字延迟自动保存和保存状态反馈。
- 建立三份轮换恢复副本、校验和恢复流程。

### 产生结果

- 测试数据退出应用后仍能读取。
- 多表关联操作要么全部成功，要么全部失败。
- 主数据模拟损坏时可以尝试读取最近有效副本。

### 验收

- 数据库创建、升级、事务回滚和恢复自动测试通过。
- 应用退出、重新打开后数据不重置。
- 恢复副本不包含 API Key。
- 迁移失败不会自动清空数据库。

## 步骤四：手工目标与计划基础流程

### 修改内容

- 实现创建目标、保存草稿、编辑目标和目标详情基础功能。
- 实现期限型目标与长期习惯的已确认字段和校验。
- 实现手工添加计划、阶段与任务，不依赖模型 API。
- 实现目标暂停、恢复、完成、终止和删除的基础状态逻辑。

### 产生结果

- 没有 API 配置时，用户仍能建立目标和手工任务。
- 目标和任务重新打开后保持原状态。

### 验收

- 两种目标类型的必填项、日期范围和状态转换符合 PRD。
- 暂停、恢复、完成和终止不会丢失关联数据。
- 未经确认的计划不会生成正式任务。

## 步骤五：模型配置与密钥安全

### 修改内容

- 实现多套 API 配置列表、编辑、删除、设为默认和测试连接入口。
- 使用 SecureStore 保存 API Key，SQLite 只保存密钥引用。
- 实现 Chat Completions 与 Responses 两种配置类型。
- 提供 DeepSeek、豆包、通义千问、智谱 GLM 和通用兼容接口的配置提示。

### 产生结果

- 用户可以保存和切换多套模型配置。
- API Key 默认隐藏，业务备份和日志中没有密钥正文。
- 测试连接不会自动保存配置或改变默认配置。

### 验收

- 使用模拟接口验证成功和各类错误提示。
- 删除配置会同时删除对应 SecureStore 密钥。
- 清除全部数据会主动删除已知密钥。
- 真实服务商测试仍保持关闭，等待用户单独授权。

## 步骤六：AI 追问与计划生成

### 修改内容

- 实现目标信息整理、AI 追问、回答保存和修改流程。
- 实现双接口请求适配、15 秒连接测试、90 秒生成超时和用户取消。
- 实现结构化输出、JSON 降级、本地解析和计划规则校验。
- 实现失败后保留输入、手动重试、切换配置和手工继续。

### 产生结果

- 模拟模型可以生成有效计划草稿。
- 超时、断网、格式错误或取消不会丢失用户输入。
- AI 结果不会未经审核直接成为正式任务。

### 验收

- 所有错误分支使用模拟接口通过自动测试。
- 不发生后台自动重试和重复调用。
- 无效日期、缺少字段、任务冲突和超限结果被阻止。

## 步骤七：计划审核、修改与确认

### 修改内容

- 实现 AI 计划草稿展示、阶段与任务编辑、警告提示和旧草稿恢复。
- 实现确认前校验和确认后原子化生成正式计划与任务。
- 建立重新生成、重新规划和旧任务替换记录。

### 产生结果

- 用户可以审核、修改、恢复并确认 AI 计划。
- 确认失败不会留下半套正式任务。
- 被新计划替换的旧任务可以作为历史查看，但不再参与通知和完成率。

### 验收

- 草稿与正式数据边界清楚。
- 重复点击确认不会重复创建任务。
- 修改日期或任务依赖后能够重新校验。

## 步骤八：今日、逾期与任务打卡

### 修改内容

- 实现今日页面中“逾期”和“今日”两个独立区域。
- 逾期任务按目标分类；今日任务按时间排序并标注所属目标。
- 实现完成、取消完成、延后、跳过、删除和重新安排。
- 实现任务详情、编辑及目标进度重新计算。

### 产生结果

- 用户可以完成完整的每日执行闭环。
- 同一任务从今日、目标和日历入口看到一致状态。

### 验收

- 逾期动态计算正确，不作为容易失真的固定状态保存。
- 每次操作立即保存实际时间和操作记录。
- 删除任务进入最近删除，恢复后重新校验时间和依赖。

## 步骤九：目标、日历、记录与设置页面

### 修改内容

- 补齐目标列表、目标详情、计划、任务、日历和记录页面。
- 补齐通知设置、最近删除、数据与隐私和应用说明。
- 实现已确认的筛选、排序、状态展示和页面跳转。

### 产生结果

- 页面原型中 MVP 范围内的主要页面可以完整访问。
- 用户能够从多个入口查看同一份本地数据。

### 验收

- 页面内容、空状态和操作入口与已确认原型一致。
- 不增加未经确认的页面、底部导航项或统计功能。

## 步骤十：本地通知与一致性修复

### 修改内容

- 实现通知权限说明与申请。
- 实现约 60 条最近通知滚动安排、通知标识保存和任务变化后的取消重排。
- 实现启动时任务与系统通知核对，以及失败后的待修复状态。
- 在 Expo Go 中验证基础本地通知。

### 产生结果

- 有效任务可以安排一次本地通知。
- 完成、跳过、删除、暂停或改期后不会保留已知无效通知。
- 权限被拒绝时任务仍然保留。

### 验收

- 通知窗口、重排和错误恢复自动测试通过。
- Expo Go 完成权限、基础调度和点击正文进入任务的真机验证。
- “完成”和“延后”通知快捷操作标记为等待独立构建验收。

## 步骤十一：鼓励动画、深色模式与易用性收尾

### 修改内容

- 实现已确认的目标完成和长期习惯阶段鼓励动画。
- 实现同一完成事件不重复自动播放及减少动态效果适配。
- 完成深色模式、文字缩放、触控区域、键盘和错误提示检查。
- 优化长列表和数据加载性能，但不改变已确认布局。

### 产生结果

- 完成目标后获得已确认的鼓励反馈。
- 深色模式和减少动态效果行为一致。

### 验收

- 动画触发、跳过和重复播放规则正确。
- 核心流程在大字号下仍可操作。
- 常用页面没有明显卡顿或遮挡。

## 步骤十二：MVP 集成测试与 Expo Go 验收

### 修改内容

- 执行完整自动测试、静态检查和主要用户流程回归。
- 在 iPhone 16 Pro Max（iOS 26.6）进行 Expo Go 真机验收。
- 在用户单独授权并提供手机端配置后，执行 DeepSeek 和豆包真实连接及计划样例测试。
- 汇总已通过、失败和等待独立构建的验收项。

### 产生结果

- 形成 Expo Go 阶段的可用 MVP 验收报告。
- 明确列出独立 iOS 构建前仍未完成的事项。

### 验收

- PRD 中可在 Expo Go 验证的 MVP 验收项全部有结果。
- 关键数据在退出、重新打开和模拟异常后不重置。
- 真实 API 测试不泄露密钥，费用由用户事前知情。

## 步骤十三：独立 iOS 构建（延期决策项）

本步骤不随“开始开发”自动执行。应用基本完成后，用户需要重新决定是否开通 Apple Developer Program。

如果用户届时接受：

- 配置 EAS iOS 签名和独立构建。
- 安装到用户注册的 iPhone。
- 验证独立图标、启动、通知快捷操作、关机重启、后台行为、SecureStore 和数据库恢复。
- 修复仅在独立构建中出现的问题。

如果用户届时仍不接受：

- 保持 Expo Go 使用方式。
- 明确说明它不是长期独立交付版本及其限制。
- 不把尚未完成的原生验收项标记为通过。

## 5. 建议执行批次

为减少频繁的小问题，同时保留关键确认，建议按以下批次汇报：

| 批次 | 包含步骤 | 阶段结果 |
|---|---|---|
| A | 步骤一至三 | 项目骨架、导航基础和可靠本地数据层 |
| B | 步骤四至七 | 目标创建、模型配置、AI 生成和计划确认闭环 |
| C | 步骤八至十 | 每日执行、完整数据查看和本地通知闭环 |
| D | 步骤十一至十二 | 视觉收尾、自动测试和 Expo Go MVP 验收 |
| E | 步骤十三 | 可选的独立 iOS 构建与最终原生验收 |

每个批次内部按照步骤顺序推进。遇到数据安全、真实收费调用、账号登录、技术方案冲突或独立构建等关键事项时单独暂停确认；普通实现细节采用文档中的推荐方案，不反复提问。

## 6. 开发完成定义

Expo Go 阶段 MVP 完成需要同时满足：

- 步骤一至十二的适用验收项通过。
- PRD、用户流程和页面原型中的 MVP 功能可以形成完整闭环。
- 自动测试和静态检查通过。
- iPhone 16 Pro Max 上的 Expo Go 验收完成。
- DeepSeek、豆包真实测试已经获得用户单独授权并记录结果，或明确标记为因缺少账号配置而未执行。
- 所有等待独立构建的项目被明确列出，没有被误报为完成。

独立 iOS 版本完成还需要：

- 用户另行确认 Apple Developer Program 和 EAS 独立构建。
- 步骤十三的真机验收通过。
- 应用可以脱离 Expo Go，以独立“橙橙计划”形式长期安装和使用。
